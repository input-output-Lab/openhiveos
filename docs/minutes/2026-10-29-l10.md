## 2. IDS

### Issue 1 — Task lifecycle (Silas)

**Identify.**
- `done` is reachable only via project-owner approval (M3 gate, `src/utilities/update-task.ts`). There is no timeout, escalation, approval queue or reviewer field.
- `pending-close` is invisible: excluded from REST `VALID_TASK_STATUSES` (`src/squad-api/routes/tasks.ts:30`) and the MCP `query_tasks` status enum.
- Status lists are defined in five places and disagree (DB CHECK, `TaskStatus`, `update_task`, REST, `query_tasks`).
- There is no status history and no task timestamps, so aging cannot be measured.
- Agent instructions contradict each other on the final status (`review` vs `pending-close`) and on the approver (Elizabeth vs Founder vs project owner).

**Discuss — what Jira and Linear do.**
- **Jira:** transition conditions, validators and post-functions; a *resolution* field separating "closed" from "how closed"; automation rules for stale items and PR merge.
- **Linear:** fixed status categories; PR merge closes issues; auto-close for stale items; cycle rollover; no approval gate.
- **Not adopted:** Jira's per-project custom workflows.

**Solve.**
- Status categories plus a `resolution` field (`completed | wont_do | duplicate | obsolete | auto_closed`).
- `reviewer_agent_slug` with domain defaults.
- Explicit transition ownership.
- Aging and escalation policy.
- Auto-close of stale `pending-close`.
- PR merge → `pending-close`.
- One-time cleanup of the 100 stuck tasks.

### Issue 2 — Estimates vs real time (Murphy)

**Identify.**
- Estimates come from the `hour-estimation` skill as Markdown only.
- No estimate columns, worklogs, status history or task timestamps exist.
- `tool_invocations` and `llm_usage` cannot be joined to tasks.

**Discuss.**
- Three distinct measures must not be conflated: **cycle time** (flow, never billed), **effort** (worklogs, agent auto + human manual) and **cost** (LLM).
- Jira's estimate/time-spent/worklog model is the right reference.
- Linear has no time tracking.

**Solve.** Store estimates as typed numeric fields with versioned history; add worklogs (`log_time`), auto-derived agent active time and an internal budget view.

### Issue 3 — Reporting (Clarence)

**Identify.**
- Only LLM-cost endpoints and the ROI portfolio exist.
- The L10 scorecard is currently hand-written.

**Solve.**
- Build a shared report service, exposed first as the MCP tool `generate_report{scope: project|hive, period, format}` with Markdown output, then as REST, then as dashboard views.
- Every report section labels its data source and coverage.
- Phasing:
  - **v1:** what exists now.
  - **v2:** flow metrics, after status history.
  - **v3:** estimate vs actual, after worklogs.

### Issue 4 — Auditing (Scout)

**Identify.**
- `/health` only checks DB connectivity and table presence.
- Nothing detected the status drift or the 100 stuck tasks.

**Solve.**
- **Invariant library** covering:
  - contract invariants
  - data invariants
  - workflow invariants
  - liveness of crons, the sync queue and workers
  - seal integrity
  - tool error rate and p95 latency
- **Execution:** a read-only `audit_hive` MCP tool plus an hourly cron, with results in an `audit_runs` table and Slack alerts.
- **Mutation `audit_log`.**
- **CI contract test** comparing the DB CHECK constraint with every schema. This test would have caught the `pending-close` drift.

### Added by the Founder — Agent configuration (The One)

**Identify.**
- All agents derive from one template (`agents/one/agent-outline.md` and the `one.ts` scaffold). The template:
  - hardcodes `report_usage` zeros and a fixed model;
  - references a non-existent `get_session_usage` tool;
  - tells assignees to write owner-only `notes` when blocked.
- `one` and `zero` are missing from `squad.manifest.json`.
- Several agents lack `report_usage` in their tool lists.

**Solve.**
- Hotfix the template now.
- Then move the OpenHive protocol into one shared include, enforced by `/api/one/validate-agent` in CI.
- Bump the manifest to 1.2.0 and re-seal.

### Added by the Founder — LLM usage under-utilised (Murphy)

**Identify.** The empty data is a design problem, not an agent-discipline problem:
- Agents cannot see their own token counts in VS Code.
- The template instructs them to send zeros.
- SEC-C9 makes cost mandatory while the caller cannot know it.
- The existing feature (commit `26577e7`, ARCH-015 v1.2) is the only wired path: gateway `tool_invocations` plus agent self-report.

**Solve.**
- Enrich `tool_invocations` and `llm_usage`.
- Add a models registry with aliases.
- Revise SEC-C9 to allow server-estimated cost, flagged as such.
- Run a spike to evaluate other sources:
  - the VS Code Copilot session store (agent name, per-turn timestamps — verified);
  - Copilot debug logs;
  - GitHub Copilot premium-request usage;
  - Bridge / Claude Code exact usage.
